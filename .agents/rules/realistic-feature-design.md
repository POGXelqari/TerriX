# Realistic Feature Design & Communication Rule

1. **Eliminate Forced "Tactical / Sci-Fi" Jargon**:
   - Do not force "tactical", "military", "briefing", or "cyber-command" roleplay jargon into standard software features, UI copy, or web verification tasks.
   - Keep design grounded, clean, realistic, and professional.

2. **Standard Real-World Verification Gateway Tasks**:
   - Human verification checkpoints must emulate standard, real-world key system funnels (e.g., Linkvertise / LootLabs style):
     - Stage 1: Visiting an external partner link / reading a sponsored article.
     - Stage 2: Exploring/installing promoted software (e.g., OperaGX, gaming tools, apps).
     - Stage 3: Watching a video from start to finish with completion tracking.
   - Enforce server-side hidden timers and state validation without exposing artificial jargon to the user.

3. **Neutral, Non-Biased Scope**:
   - Avoid forcing TerriX lore onto every page or detail.
   - Web verification funnels should function like clean, modern third-party gateway checkpoints with normal consumer UX.
