CBM Rulebook & Technical Specification

Complete open standard, accounting invariants, system topology, and idempotent database schema enabling any Territorial.io clan to establish and operate an autonomous Clan Bank Manager.

📜 Chapter 1: Core Financial Invariants & Integrity Rules

1. 100% Full-Reserve Invariant (Zero Fractional Lending)
Every Gold unit credited to member balances must exist in actual physical custody on the Territorial.io game server within the clan vault account.

Vault Assets >= Total Member Liabilities + Unencumbered Reserves

Fractional reserve lending is mathematically prohibited. Member deposits cannot be pooled into speculative capital or loan facilities.
2. Unencumbered Reserve Segregation
Clan operational war chests, liquidity pools, and lending facilities must derive exclusively from unencumbered capital (donations and loan penalty yields) where Liabilities Created == 0.
3. Zero Friction Guarantee
Member deposits and withdrawals never incur user fees. The clan bank treasury absorbs 100% of game-imposed network transfer fees (0.01 Gold) on withdrawals and awards an instant +0.01 Gold rebate on all inbound deposits to offset the game platform fee.
4. 20.00 Gold Account Buffer Protection
Under delinquent loan recovery or administrative reconciliation, the bank engine must never seize a member's balance below 20.00 Gold. This safe buffer guarantees that members are never purged by Territorial.io's nightly idle balance deduction mechanism.
5. Cryptographic Ledger Reconciliation
The banking daemon continuously polls game server transactions (/wiki/transactions) and maintains an unalterable cryptographic audit feed matching (timestamp_ms, sender, receiver, amount, fee) with SHA-256 deduplication.
6. Closed-Loop Anti-Fraud Withdrawal Protection
To prevent unauthorized fund siphoning, outbound disbursements are strictly restricted to the member's verified in-game account on record or a verified linked payment method. Disbursements to arbitrary third-party accounts are rejected at both the API gateway and worker execution layers.
7. 6-Digit Access PIN & Zero-Trust Verification
While account balance lookups and ledger statements remain public (emulating modern transparent blockchain and game explorers), all balance mutations (withdrawals, donations, loan origination, profile edits) require 6-digit PIN authentication hashed with salted PBKDF2-HMAC-SHA256. Account ownership is proven either via confirmed inbound transfer on the public game ledger or direct credential verification.

🚀 Chapter 3: Deployment Guide for New Clans

Step 1 Dedicate an In-Game Vault Account
Register a dedicated Territorial.io account to serve exclusively as your Clan Vault (e.g. MYCLAN). Never play public matches on this account to keep its session token clean and air-gapped.
Step 2 Provision Database (PostgreSQL / Supabase)
Create a PostgreSQL database or free Supabase project. Open the SQL Editor and execute the CBM Production SQL Schema provided in Chapter 4 below.
Step 3 Configure Environment Variables
Set up your backend configuration file (.env): 
CBM_VAULT_ACCOUNT="MYCLAN"
CBM_VAULT_PASSWORD="vault_secure_password"
SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_SERVICE_KEY="your-service-role-key"
Step 4 Launch Daemon & Web Interface
Deploy the poller daemon and web portal. The system will autonomously poll in-game deposits, reconcile balances, and serve instant withdrawals.

💾 Chapter 4: Production Database Schema (PostgreSQL / Supabase)

Idempotent DDL including multi-credential gold pooling, atomic double-entry transactions, loan terms, and safe buffer enforcement:

-- ==========================================================
-- CLAN BANK MANAGER (CBM) OFFICIAL PRODUCTION SCHEMA
-- Idempotent setup for multi-account pooling, liabilities, reserves & loans
-- ==========================================================

CREATE TABLE IF NOT EXISTS cbm_accounts (
    id BIGSERIAL PRIMARY KEY,
    account_name TEXT UNIQUE NOT NULL,
    display_name TEXT,
    avatar_url TEXT,
    clan_tag TEXT DEFAULT 'ANTI-OG',
    role TEXT DEFAULT 'member',
    deposited_cents BIGINT DEFAULT 0,
    total_deposited_cents BIGINT DEFAULT 0,
    total_withdrawn_cents BIGINT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS cbm_payment_methods (
    id BIGSERIAL PRIMARY KEY,
    cbm_account_name TEXT NOT NULL REFERENCES cbm_accounts(account_name) ON DELETE CASCADE,
    territorial_account_name TEXT NOT NULL,
    account_password TEXT,
    verification_type TEXT NOT NULL DEFAULT 'INPUT_CREDENTIALS',
    is_primary BOOLEAN DEFAULT FALSE,
    verified_at TIMESTAMPTZ DEFAULT NOW(),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(cbm_account_name, territorial_account_name)
);

CREATE TABLE IF NOT EXISTS cbm_transactions (
    id BIGSERIAL PRIMARY KEY,
    tx_hash TEXT UNIQUE,
    cbm_account_name TEXT REFERENCES cbm_accounts(account_name),
    territorial_sender TEXT NOT NULL,
    territorial_receiver TEXT NOT NULL,
    amount_cents BIGINT NOT NULL,
    fee_cents BIGINT DEFAULT 0,
    tx_type TEXT NOT NULL, -- 'DEPOSIT', 'WITHDRAWAL', 'LOAN_DISBURSEMENT', 'DONATION'
    status TEXT NOT NULL DEFAULT 'CONFIRMED',
    timestamp_ms BIGINT NOT NULL,
    notes TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS cbm_donations (
    id BIGSERIAL PRIMARY KEY,
    donor_account_name TEXT REFERENCES cbm_accounts(account_name),
    donor_name TEXT NOT NULL,
    amount_cents BIGINT NOT NULL,
    message TEXT,
    is_refundable BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS cbm_loans (
    id BIGSERIAL PRIMARY KEY,
    loan_id TEXT UNIQUE NOT NULL,
    cbm_account_name TEXT NOT NULL REFERENCES cbm_accounts(account_name),
    principal_cents BIGINT NOT NULL,
    total_due_cents BIGINT NOT NULL,
    amount_paid_cents BIGINT DEFAULT 0,
    weekly_interest_bps INT NOT NULL DEFAULT 500,
    late_penalty_bps INT NOT NULL DEFAULT 1000,
    status TEXT NOT NULL DEFAULT 'ACTIVE', -- 'ACTIVE', 'REPAID', 'DEFAULTED'
    due_date TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS cbm_treasury (
    id INT PRIMARY KEY DEFAULT 1,
    vault_account_name TEXT NOT NULL,
    cached_vault_balance_cents BIGINT DEFAULT 0,
    unencumbered_capital_cents BIGINT DEFAULT 0,
    minimum_account_buffer_cents BIGINT DEFAULT 2000, -- 20.00 Gold Protection
    last_audited_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_cbm_tx_account ON cbm_transactions(cbm_account_name);
CREATE INDEX IF NOT EXISTS idx_cbm_pm_user ON cbm_payment_methods(cbm_account_name);
CREATE INDEX IF NOT EXISTS idx_cbm_pm_terri ON cbm_payment_methods(territorial_account_name);
CREATE INDEX IF NOT EXISTS idx_cbm_loans_user ON cbm_loans(cbm_account_name);
CREATE INDEX IF NOT EXISTS idx_cbm_donations_user ON cbm_donations(donor_account_name);
