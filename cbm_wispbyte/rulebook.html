📜 Chapter 1: Core Financial Invariants & Integrity Rules

1. 100% Full-Reserve Invariant (Zero Fractional Lending)
Every Gold unit credited to member balances must exist in actual physical custody on the Territorial.io game server within the clan vault account.

Vault Assets >= Total Member Liabilities + Unencumbered Reserves

Fractional reserve lending is mathematically prohibited. Member deposits cannot be pooled into speculative capital or loan facilities.
2. Unencumbered Reserve Segregation
Clan operational war chests, liquidity pools, and lending facilities must derive exclusively from unencumbered capital (donations and loan penalty yields) where Liabilities Created == 0.
3. Zero Friction Guarantee
Member deposits and withdrawals never incur user fees. The clan bank treasury absorbs 100% of game-imposed network transfer fees (0.01 Gold) on withdrawals and awards an instant +0.01 Gold rebate on all inbound deposits to offset the game platform fee.
4. 20.00 Gold Account Buffer Protection
Under delinquent loan recovery or administrative reconciliation, the bank engine must never seize a member's balance below 20.00 Gold. This safe buffer guarantees that members are never purged by Territorial.io's nightly idle balance deduction mechanism.
5. Cryptographic Ledger Reconciliation
The banking daemon continuously polls game server transactions (/wiki/transactions) and maintains an unalterable cryptographic audit feed matching (timestamp_ms, sender, receiver, amount, fee) with SHA-256 deduplication.
6. Closed-Loop Anti-Fraud Withdrawal Protection
To prevent unauthorized fund siphoning, outbound disbursements are strictly restricted to the member's verified in-game account on record or a verified linked payment method. Disbursements to arbitrary third-party accounts are rejected at both the API gateway and worker execution layers.
7. 6-Digit Access PIN & Zero-Trust Verification
While account balance lookups and ledger statements remain public (emulating modern transparent blockchain and game explorers), all balance mutations (withdrawals, donations, loan origination, profile edits) require 6-digit PIN authentication hashed with salted PBKDF2-HMAC-SHA256. Account ownership is proven either via confirmed inbound transfer on the public game ledger or direct credential verification.

🚀 Chapter 3: Deployment Guide for New Clans

Step 1 Dedicate an In-Game Vault Account
Register a dedicated Territorial.io account to serve exclusively as your Clan Vault (e.g. MYCLAN). Never play public matches on this account to keep its session token clean and air-gapped.
Step 2 Provision Database (PostgreSQL / Supabase)
Create a PostgreSQL database or free Supabase project. Open the SQL Editor and execute the CBM Production SQL Schema provided in Chapter 4 below.
Step 3 Configure Environment Variables
Set up your backend configuration file (.env): 
CBM_VAULT_ACCOUNT="MYCLAN"
CBM_VAULT_PASSWORD="vault_secure_password"
SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_SERVICE_KEY="your-service-role-key"
Step 4 Launch Daemon & Web Interface
Deploy the poller daemon and web portal. The system will automatically poll in-game deposits, reconcile balances, and serve instant withdrawals.
